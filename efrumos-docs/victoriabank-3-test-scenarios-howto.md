# Как прогнать 3 тестовых сценария VictoriaBank и получить RRN

Банк (после подтверждения терминала `49807132`) просит провести 3 карточные
транзакции по тестовым сценариям и прислать `RRN` каждой. Здесь — по шагам.

**Тестовая карта банка** (из онбординг-письма, реальные деньги НЕ списываются):
- Номер: `5298 5899 8959 7523`
- Срок: `03/32`
- CVV: `118`

Все шаги делаются на **dev** (`dev.efrumos.md`) — там тестовый эндпоинт
банка (`https://ecomt.victoriabank.md/cgi-bin/cgi_link`), а не боевой.

---

## Подготовка (один раз)

На сервере, в `/var/www/dev.efrumos.md`:

1. **Ключи на месте:**
   ```bash
   ls -la storage/app/victoriabank-keys/
   ```
   Должно быть 3 файла: `bank_public.pem`, `merchant_private.pem`, `merchant_public.pem`.
   Если нет — синхронизировать деплоем заново или скопировать вручную с локальной машины.

2. **Включить оплату картой** — в `.env`:
   ```
   ONLINE_PAYMENT_ENABLED=true
   ```
   Затем перечитать конфиг:
   ```bash
   docker restart php8.2-dev_efrumos_md
   ```

3. **Проверить, что эндпоинт тестовый** — в `.env` должно быть
   `APP_ENV=stage` (или `local`), НЕ `production`. Тогда
   `config/services.php` сам выберет тестовый адрес банка.

4. **Проверить сайт:** `curl -I https://dev.efrumos.md/ru/` → `HTTP/2 200`.

---

## Тест 1 — успешная оплата (`0` → `21`)

**Что проверяем:** обычная покупка, деньги списаны полностью.

1. Открыть `https://dev.efrumos.md/ru/`, добавить любой товар в корзину.
2. Оформить заказ, заполнить данные, выбрать **оплату картой**.
3. Перебросит на страницу банка — там будет красная надпись **TEST MODE**
   (это нормально, значит тестовый режим).
4. Ввести тестовую карту (см. выше), подтвердить.
5. Вернёт на сайт на страницу «Заказ оплачен».
6. Наш код после callback банка **сам** делает `TRTYPE=21` (капчур).

**Достать RRN** — на сервере:
```bash
docker exec php8.2-dev_efrumos_md php artisan tinker --execute="
print_r(\App\Models\OrderPayment::where('provider','victoriabank')->latest('id')->first()->only(['orders_id','rrn','int_ref','provider_status','confirmed_at']));
"
```
- `provider_status` должен быть `CAPTURE RC=00` — значит капчур прошёл.
- Записать `rrn` → это RRN для теста 1.

## Тест 2 — авторизация + отмена, БЕЗ списания (`0` → `24`)

**Что проверяем:** деньги были заблокированы на карте, но капчур не делали —
блокировку снимают, списания не было.

1. В `.env` на dev включить флаг:
   ```
   VICTORIABANK_SKIP_AUTOCAPTURE=true
   ```
   ```bash
   docker restart php8.2-dev_efrumos_md
   ```
   (этот флаг существует только для этого теста — он говорит коду НЕ делать
   авто-капчур после авторизации.)

2. Тот же флоу: корзина → оформление → оплата картой → тестовая карта на
   странице банка → подтвердить → вернуться на сайт.

3. В этот раз капчура НЕ будет. Заказ останется в статусе «ожидает оплаты»
   (`payment_status = pending`), в логе будет
   `авто-капчур пропущен (VICTORIABANK_SKIP_AUTOCAPTURE)`.

4. Достать данные транзакции:
   ```bash
   docker exec php8.2-dev_efrumos_md php artisan tinker --execute="
   \$p = \App\Models\OrderPayment::where('provider','victoriabank')->latest('id')->first();
   echo 'orders_id='.\$p->orders_id.PHP_EOL;
   echo 'rrn='.\$p->rrn.PHP_EOL;
   echo 'int_ref='.\$p->int_ref.PHP_EOL;
   echo 'amount='.(\$p->amount_bani/100).PHP_EOL;
   echo 'provider_status='.\$p->provider_status.PHP_EOL;
   "
   ```
   `provider_status` должен быть `ACTION=0 RC=00` (авторизация прошла), БЕЗ
   строки `CAPTURE`.

5. **Отменить авторизацию** (`TRTYPE=24`):
   ```bash
   docker exec php8.2-dev_efrumos_md php artisan tinker --execute="
   \$p = \App\Models\OrderPayment::where('provider','victoriabank')->latest('id')->first();
   \$c = \App\Services\Payment\Victoriabank\VictoriaBankClient::fromConfig();
   \$res = \$c->reverse((string)\$p->orders_id, \$p->amount_bani/100, \$p->rrn, \$p->int_ref);
   print_r(\$res);
   "
   ```
   В ответе смотреть `RC` — `00` значит отмена прошла (`RC=95` — «уже
   отменено», тоже не ошибка, если случайно вызвали дважды).

6. **ВЕРНУТЬ ФЛАГ ОБРАТНО** — в `.env`:
   ```
   VICTORIABANK_SKIP_AUTOCAPTURE=false
   ```
   ```bash
   docker restart php8.2-dev_efrumos_md
   ```

**RRN для теста 2** — тот же `rrn` из шага 4 (отмена ссылается на ту же
транзакцию, нового номера не создаёт).

## Тест 3 — полный цикл с возвратом (`0` → `21` → `24`)

**Что проверяем:** обычная завершённая покупка (деньги реально списаны), а
потом полноценный возврат уже списанных денег.

1. Убедиться, что `VICTORIABANK_SKIP_AUTOCAPTURE=false` (обычный режим).
2. Тот же флоу: корзина → оформление → оплата картой → тестовая карта →
   подтвердить. Заказ станет «Оплачен» (капчур `TRTYPE=21` прошёл
   автоматически, как в тесте 1).
3. Достать данные транзакции (та же команда, что в тесте 2, шаг 4).
   `provider_status` должен быть `CAPTURE RC=00`.
4. **Сделать возврат** (`TRTYPE=24` поверх уже списанной суммы) — та же
   команда `reverse()`, что в тесте 2, шаг 5.
5. В ответе `RC=00` — возврат прошёл.

**RRN для теста 3** — тот же `rrn` из шага 3.

---

## Что отправить банку

Три `RRN` (по одному на каждый тест), подписанные сценарием:

| Сценарий | RRN |
|---|---|
| Тест 1 — `0` → `21` (успешная оплата) | `___________` |
| Тест 2 — `0` → `24` (авторизация + отмена) | `___________` |
| Тест 3 — `0` → `21` → `24` (оплата + возврат) | `___________` |

Плюс, если банк просит — `INT_REF` каждой (тоже есть в выводе tinker).

---

## После всех тестов

1. `VICTORIABANK_SKIP_AUTOCAPTURE=false` (или убрать строку из `.env`) —
   **обязательно**, иначе в обычной работе оплаты не будут финализироваться.
2. `ONLINE_PAYMENT_ENABLED` — оставить `true` только если dev дальше нужен
   для тестов оплаты, иначе вернуть `false`.
3. `docker restart php8.2-dev_efrumos_md` после любой правки `.env`.
4. Тестовые заказы можно оставить или удалить через админку — на боевые
   данные они не влияют (dev-база отдельная).
